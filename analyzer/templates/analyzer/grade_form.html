🟢 Well-Optimized Queries (Grade: A-B)

Efficient JOIN with Proper Indexing
SELECT u.name, u.email, COUNT(o.id) as order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.created_at >= '2023-01-01'
  AND u.status = 'active'
GROUP BY u.id, u.name, u.email
HAVING COUNT(o.id) > 0
ORDER BY order_count DESC
LIMIT 100;
Proper UNION ALL Usage
SELECT name, email FROM active_users
WHERE created_at >= '2024-01-01'
UNION ALL
SELECT name, email FROM inactive_users
WHERE last_login >= '2023-01-01'
ORDER BY name;

🟡 Moderate Issues (Grade: C-D)

UNION Without ALL (Performance Issue)
SELECT product_name, category FROM products
WHERE price > 100
UNION
SELECT product_name, category FROM archived_products
WHERE archived_date > '2023-01-01'
ORDER BY product_name;
Functions in WHERE Clause
SELECT * FROM users
WHERE UPPER(email) LIKE '%@GMAIL.COM'
  AND YEAR(created_at) = 2024
  AND LENGTH(name) > 5
ORDER BY created_at DESC;
Misused HAVING Clause
SELECT department, COUNT(*) as emp_count
FROM employees
GROUP BY department
HAVING department = 'Sales'
  AND emp_count > 10
ORDER BY emp_count DESC;

🔴 Serious Problems (Grade: D-F)

Slow Correlated Subquery
SELECT u.name, u.email,
  (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) as order_count,
  (SELECT MAX(o.total) FROM orders o WHERE o.user_id = u.id) as max_order
FROM users u
WHERE u.status = 'active';
Dangerous Cartesian Product
SELECT *
FROM users u, orders o, products p
WHERE u.created_at > '2024-01-01'
  AND o.total > 100;
Query with Multiple Issues
SELECT DISTINCT *
FROM users u
WHERE UPPER(u.email) LIKE '%@%'
  AND u.id NOT IN (
    SELECT user_id FROM orders
    WHERE user_id IS NOT NULL
  )
ORDER BY SUBSTRING(u.name, 1, 5);
